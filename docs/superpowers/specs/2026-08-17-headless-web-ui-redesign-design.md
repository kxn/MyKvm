# Headless Web UI 全面重设计

日期：2026-08-17
状态：待评审（评审通过后再拆单）
关联文档：`2026-08-04-headless-web-ui-design.md`（现状设计的长期事实来源，本文落地后将取代其 UI 组织部分）

## 1. 背景与目标

headless 模块的 Web 控制台（`crates/ipkvm-headless/web/`）目前的 UI 是按"桌面端功能平移到 Web 工具栏"的思路组织的：顶部工具栏平铺 8 个控件，特殊键 26 项平铺成 5 组下拉，设置弹层单层堆叠全部字段，状态面板面向调试。功能本身完整，但对一般使用者的顺畅度和现代感不足。

本文在不改动后端 API、不新增后端功能的前提下，重新设计整套 UI 的信息架构、布局、视觉和操作流程，目标：

- 一般使用者（不是开发者）不读文档就能完成连接、键鼠操作、粘贴、发特殊键、截图、看状态。
- 界面观感现代：双主题（深/浅）、有层次的信息密度、克制统一的控件语言。
- 信息架构为将来可能加入的虚拟媒体、电源控制等能力预留位置，避免届时再推翻。

## 2. 现状事实摘要

（详细清单见探索结论，此处只列与重设计相关的事实。）

- 前端为纯原生 HTML/CSS/ES module，无构建链、无 CDN；`web/` 与 vendored noVNC 1.7.0 一起经 `include_dir!` 编译期嵌入二进制。noVNC 仅作 RFB 客户端库，有本地 patch（相对指针 0x08/0x09 消息等）。
- 页面只有两个：`index.html`（控制台）和 `licenses.html`。
- 控制台是单页两视图：`#connection-view`（选视频/串口设备 + profile → 连接）和 `#video-view`（noVNC 画布 + 底部状态栏），由轮询 `/api/status` 的状态机切换。
- 顶部工具栏控件：`断开`、`粘贴`、`设置`、`特殊键▾`（5 组 26 项）、`截图▾`（保存/复制）、`语言` 下拉、`状态`（可拖动调试面板）、GitHub 外链。
- 设置弹层字段：波特率、自动波特率（仅存不消费）、预览帧率、默认鼠标模式、目标端兼容 profile、相对灵敏度、缩放模式。
- "目标端兼容 profile" 同一份控件出现在三个位置：连接页、视频页底部状态栏、设置弹层。
- 视频页底部状态栏信息混杂：分辨率、设备名、会话状态、串口统计（批/帧）、输入事件数、profile 下拉、相对模式按钮。
- 无虚拟媒体、ATX 电源、用户管理；认证为可选静态 token（`?token=` 首访换 HttpOnly cookie），无登录页。
- i18n 为自写 zh-CN/en 文案表；浏览器端测试用 playwright-core（`browser-tests/`）。

## 3. 现状问题诊断

从"一般使用者"视角看，当前 UI 的主要问题：

1. **工具栏无分组、无主次**：会话控制（断开）、输入辅助（粘贴/特殊键）、画面操作（截图）、全局配置（设置/语言）、调试（状态）8 个控件平铺一排，认知负担全在首次使用者身上。
2. **特殊键菜单过度暴露**：26 项平铺，其中大量是浏览器场景快捷键（Ctrl+Shift+I 开发者工具等），普通用户只需要 Ctrl+Alt+Del、Alt+Tab 等少数几项。
3. **调试信息与用户状态混排**：底部状态栏的"串口批/帧、输入事件数"是链路诊断数据，不该默认占用户视野。
4. **设置无层次**：会话级（缩放、鼠标模式）与设备级（波特率、帧率）混在一个弹层；profile 三处重复出现，用户不知道改哪里才生效。
5. **连接页暴露技术细节**：探测状态、波特率摘要等原始信息直接铺开，缺少"一键用默认连接"的主路径。
6. **视觉语言陈旧**：浅色单主题、控件样式零散，无统一设计 token。

## 4. 设计决策（已与维护者确认）

- **范围**：功能清单不变，纯前端重设计；信息架构预留虚拟媒体、电源控制等未来扩展位。
- **目标设备**：只做桌面浏览器，不做移动端适配。
- **视觉**：深/浅双主题，跟随系统 + 手动切换。
- **技术栈**：见第 5 节的权衡结论。

## 5. 技术栈建议：保持无构建链

结论：**不引入前端构建链和框架**，继续使用纯原生 ES module + vendored noVNC + `include_dir!` 嵌入。

理由：

- 单二进制、零外部资源是该产品的部署形态核心（拷一个可执行文件即可跑），引入 npm 构建链会让发布流程、贡献者门槛、可复现构建全部复杂化，收益不成比例。
- "现代 UI"的观感主要来自设计语言（配色 token、间距体系、层级、动效、图标），而不是框架。本文的组件（工具条、popover、抽屉、toast、对话框、标签页）全部是自写一百行以内的原生实现，现有代码已有同类先例（menu-panel、modal、状态面板）。
- noVNC 已 vendored 且有本地 patch，保持现状无额外成本。

代价与风险：

- 组件靠自写，需要自律地维护一套统一的 CSS 设计 token（第 8 节），否则会退化回零散样式。缓解：把设计 token 和基础组件样式集中在 `app.css` 前半部分，页面样式在后。
- 若未来功能（虚拟媒体文件管理、日志查看等）把前端复杂度推过临界点，再单独评估迁移，届时信息架构（第 6 节）不依赖具体实现技术，可以直接平移。

## 6. 信息架构

### 6.1 整体结构：会话中心，三态视图

```
┌─ 未连接 ─┐   ┌─ 会话中（默认态） ─┐   ┌─ 异常/恢复中 ─┐
│ 连接向导  │ → │ 全屏画面 + 悬浮控制条 │ → │ 画面内状态横幅  │
└─────────┘   └──────────────────┘   └──────────────┘
```

视图状态机与现状一致（由 `/api/status` 轮询驱动），但语义重新命名：

- **setup（连接向导）**：无会话时展示。
- **console（控制台）**：会话运行中，视频画面占满视口，控制条悬浮其上。
- **degraded（异常态）**：不是独立页面，而是 console 上的画面内横幅（"视频链路恢复中…"/"输入链路异常，点击查看诊断"），不打断用户视野。手动停止（`stop`）回到 setup。

### 6.2 控制台布局（console）

```
┌──────────────────────────────────────────────────────┐
│              （悬浮控制条，悬停/聚焦时显现）            │
│  ● 已连接 · DESKTOP-1  ⌨ 输入 ▾   🖱 鼠标 ▾   📷 ▾  ⛶ ⋯ │
├──────────────────────────────────────────────────────┤
│                                                      │
│                  noVNC 视频画面                        │
│               （占满视口，按缩放模式渲染）              │
│                                                      │
├──────────────────────────────────────────────────────┤
│ 1920×1080 · 30 fps · Windows profile   （极简状态行，可关）│
└──────────────────────────────────────────────────────┘
```

- **悬浮控制条**：默认半透明悬浮在画面顶部，3 秒无操作淡出，鼠标移到顶部或按 `Ctrl+Alt`（可配置）唤出；提供"固定"开关，固定时进入文档流把画面下推。分组与控件：
  - **会话组**：状态灯 + 目标名 + 下拉（断开连接、重新连接、连接信息）。
  - **输入组**：`特殊键`（重设计，见 6.3）、`粘贴文本`（升级为对话框，见 6.4）。
  - **鼠标组**：鼠标模式（绝对/相对切换 + 相对灵敏度滑杆）、目标端 profile 热切换——把现在底部状态栏的两个控件收进来。
  - **画面组**：截图（保存/复制）、缩放模式循环切换、全屏（浏览器 Fullscreen API，新能力，纯前端）。
  - **更多组（⋯）**：状态监控、设置、主题切换、语言、快捷键一览、许可证、GitHub。
- **极简状态行**：分辨率、帧率、当前 profile 一行文字，可在设置里关掉；诊断数据（串口批/帧、编码字节、输入事件数）全部移入状态监控面板，不再默认展示。
- **状态监控**：从"可拖动毛玻璃浮层"改为**右侧滑出抽屉（drawer）**，分组保留（视频/连接/编码/系统），视觉上区分"用户可读指标"（帧率、带宽、时长）与"诊断指标"（折叠在"高级"里）。

### 6.3 特殊键重设计

现状 26 项平铺改为**常用区 + 分类折叠 + 自定义发送**：

```
┌─ 发送按键 ──────────────────┐
│ [Ctrl+Alt+Del] [Alt+Tab]    │   ← 常用区：大按钮，4~6 个
│ [Win] [PrintScreen]         │
│ ─────────────────────────── │
│ ▸ 窗口与标签页（6）           │   ← 折叠组，点开才展开
│ ▸ 刷新与导航（5）             │
│ ▸ 开发者与查看（7）           │
│ ▸ 其它（6）                  │
│ ─────────────────────────── │
│ 自定义组合键：[Ctrl☑][Alt☐][Shift☐] + [键 ▾] [发送] │
└─────────────────────────────┘
```

- 常用区内容固定为最高频项（Ctrl+Alt+Del、Alt+Tab、Win、PrintScreen），不做"最近使用"排序（YAGNI，避免状态漂移）。
- 自定义组合键覆盖长尾需求，替代现在把 26 项全列出来的做法。
- 分类沿用现有 5 组的分组数据，只是默认折叠。

### 6.4 粘贴升级

现状直接读浏览器剪贴板，常因权限被拒或内容不符预期。改为**粘贴对话框**：

- 打开时尝试预填剪贴板内容（失败则空白并提示授权），用户可编辑确认后发送。
- 显示字符数，超长文本给警告（CH9329 逐键注入，大文本耗时）。
- 发送时给进度反馈（toast 或对话框内进度条），完成后自动关闭。

### 6.5 连接向导（setup）

```
┌─ 连接远程主机 ──────────────────┐
│  视频设备  [USB Camera       ▾] │   ← 自动枚举，唯一设备自动选中
│  串口设备  [COM9 (CH9329)    ▾] │
│  目标系统  [Windows          ▾] │   ← 原"目标端兼容 profile"，改名
│                                 │
│  ▸ 高级（波特率 · 预览帧率 · 鼠标模式）│  ← 折叠，展开即跳转设置对应分区
│                                 │
│           [ 连 接 ]             │
└─────────────────────────────────┘
```

- 探测状态（"枚举失败"等）只在失败时以内联错误出现，成功路径不展示技术细节。
- "目标端兼容 profile" 改名"目标系统"，用用户语言（Windows/Linux/BIOS/…），原始绝对/相对坐标收进高级。
- 保留"启动时已配设备则自动连接直进画面"的快路径。

### 6.6 设置：分区 + 生效时机标注

设置从单层弹层改为右侧大抽屉（或居中大对话框），左侧分区导航：

- **常规**：语言、主题（跟随系统/深色/浅色）。
- **画面**：缩放模式、预览帧率、状态行显隐。
- **输入**：默认鼠标模式、目标系统、相对灵敏度。
- **设备**：波特率、自动波特率。
- **关于**：版本、许可证入口、GitHub、诊断信息下载（后续项，预留）。

每项标注生效时机：即时生效 / 重连后生效 / 重启服务后生效。`恢复默认值`保留在底部。

### 6.7 扩展位预留

- 控制条"更多组"和右侧抽屉的 tab 结构可容纳未来的"虚拟媒体"、"电源控制"入口，届时各占一个抽屉 tab，不冲击控制台主布局。
- setup 视图未来可加"挂载 ISO 后装机"流程入口。
- 设置分区结构天然可扩展（新增分区即新增一项导航）。
- 若未来加入登录流程，`degraded` 横幅机制可复用为"认证过期，点击重新认证"。

## 7. 关键操作流程

1. **首次使用**：打开 URL → setup 向导（设备已自动枚举选中）→ 选目标系统 → 连接 → 进入 console。
2. **日常操作**：画面全屏常驻；需要特殊键/粘贴/截图时鼠标上移唤出控制条；操作完自动隐藏。
3. **鼠标不同步**：控制条鼠标组 → 切目标系统 profile，或切相对模式；无需进设置。
4. **看运行状态**：⋯→ 状态监控，右侧抽屉展开，画面继续可见。
5. **改配置**：⋯→ 设置，按分区修改，标注了生效时机；改设备类参数会提示"重连后生效"并可一键重连。
6. **断线恢复**：链路异常时画面内横幅提示 + 自动恢复（沿用 supervisor/重连机制），恢复失败给"重新连接"按钮。
7. **键盘用户**：`?` 打开快捷键一览；控制条全部可 Tab 到达；画面聚焦时按键直通 noVNC。

## 8. 视觉设计

- **设计 token**（CSS 自定义属性，集中定义）：颜色（背景三级、表面、边框、文本三级、accent、成功/警告/危险）、间距（4px 基准梯度）、圆角、阴影、字号梯度、过渡时长。深浅主题只切换 token 值，组件不感知主题。
- **深色为默认主题**（KVM 控制台主流取向，画面融入感好），`prefers-color-scheme` 首次决定默认，手动切换后存 localStorage。
- **图标**：内联 SVG 图标集（自绘或取 MIT 许可图标手工内联，不引依赖），控制条图标 + tooltip，去掉纯文字按钮的拥挤感。
- **字体与排版**：沿用系统字体栈；控制条 13px、正文 14px、标题梯度。
- **动效**：控制条淡入淡出、抽屉滑入均为 150–200ms ease，`prefers-reduced-motion` 下关闭。
- **画面优先**：console 态下 chrome（控制条、状态行）总高度占比尽量低，深色主题下 chrome 与视频画面之间无刺眼边界。

## 9. 实现约束与兼容性

- 后端 API（`/api/*`、`/rfb`）完全不动；本次改造理论上只涉及 `crates/ipkvm-headless/web/` 下的 HTML/CSS/JS。
- 设置项的持久化键（`headless-settings.toml` 字段）不变，仅重新分区展示；新增"主题""状态行显隐"两个纯前端偏好存 localStorage，不进 TOML。
- i18n 文案表随新结构重写，保持 zh-CN/en 双语；`toolbar.licenses` 之类的残留键清理。
- noVNC 及 `third_party/novnc/PATCHES.md` 的 patch 不受影响。
- 浏览器端测试（`browser-tests/novnc-browser.mjs`，playwright-core）需按新 DOM 结构更新选择器；测试覆盖面（连接流程、特殊键、粘贴、设置读写、相对模式）不变。

## 10. 验收标准（草案，拆单时细化）

- 首次使用路径：从打开页面到看到画面，不超过 3 次点击（设备唯一时 1 次）。
- 控制条 3 秒自动隐藏，唤出无延迟；固定开关生效。
- 特殊键常用区一键发送 Ctrl+Alt+Del 成功（浏览器测试断言 RFB 按键序列）。
- 粘贴对话框在剪贴板权限被拒时仍可手动输入发送。
- 深/浅主题切换即时生效且刷新后保持；`prefers-color-scheme` 首次生效。
- 全部现有功能（连接/断开/重连、profile 热切换、相对模式、截图两式、缩放三模式、状态监控四组、设置读写与恢复默认）在新 UI 中可达且行为不变。
- `cargo test --workspace --all-features` 与 `browser-tests` 全绿。

## 11. 拆单建议（评审通过后细化）

按依赖关系建议的实施顺序，待本文评审通过后正式开单：

1. 设计 token + 双主题基础设施（CSS 变量、主题切换、localStorage 偏好）。
2. 控制台骨架：悬浮控制条 + 极简状态行 + degraded 横幅，迁移现有按钮能力。
3. 特殊键面板与粘贴对话框。
4. 状态监控抽屉化。
5. 设置分区化。
6. setup 连接向导改版。
7. 浏览器测试更新与收尾（i18n 清理、残留样式删除）。

每步保持 UI 可用（不改 API、功能不回退），可以分 PR 独立合入。

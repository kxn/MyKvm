## 1. 调研范围与共同约束

本次同时检查 Gitea issue #151、#152、#153、#154、#156，现有 iced/headless 设计文档，
`ipkvm-core`、`ipkvm-desktop-core`、`ipkvm-desktop-iced`、`ipkvm-headless` 和 noVNC
补丁代码。五单共享输入行为，但职责不同：

- #151 负责目标端 OS profile 与原始鼠标模式的数据模型、配置/API 接入；
- #152 负责加载桌面连接 profile 后控制设备探测状态没有收口的 bug；
- #156 负责 Iced/Web 的键鼠调度、鼠标移动合并和控制事件顺序；
- #154 负责目标端 Relative 模式与主控端本地光标捕获的分层、区域硬锁和 Web 降级；
- #153 负责 iced 视觉令牌、弹窗尺寸和表单布局，不改变行为。

共同约束：不改 RFB 线协议、CH9329 帧格式、串口队列优先级、egui、headless 既有 API
结构或用户连接流程；新增行为必须先有失败测试；真实 Windows 光标、Pointer Lock、
CH9329 和目标机 OS 仍需记录人工验证例外。

## 2. 现状代码事实

### #151

`MouseMode` 目前只有 `Absolute`/`Relative`，桌面连接配置和 headless `WebSettings` 只
持久化 `mouse_mode`。iced 的 `ConnectionSettings` 已由 #159 收入
`ipkvm-desktop-core`，Web 设置位于 `crates/ipkvm-headless/src/settings.rs`；两侧需要
共享稳定 profile 标识，但 `ipkvm-core` 当前不依赖 serde，因此序列化适配应留在两侧。

### #152

`crates/ipkvm-desktop-iced/src/app.rs::apply_profile` 只调用
`apply_profile_to_selection`，匹配控制设备后状态停在 `Checking`。真正会调用
`probe_control` 的路径是 `Message::SelectControl` 或 `Message::RefreshDevices`；视频侧
由 `PreviewTick` 自动推进，造成同一 profile 加载后视频可用而控制永远 Checking。

### #156

Iced 的 `DeltaSampler` 只提供按周期 `feed`，按钮/滚轮没有强制冲刷接口；Web/noVNC 的
相对移动在 `third_party/novnc/1.7.0/core/rfb.js` 中每个 mousemove 立即发送，没有累计
和相对定时器。键盘路径独立，不应被鼠标采样器阻塞。#67 后 RFB server 按
`Button -> RelativeMove -> Wheel` 展开同一条相对消息，使位移携带本次按钮 mask。

### #154

iced `platform/cursor.rs` 当前用 `GetForegroundWindow` + `GetWindowRect` 把光标裁剪到
整个前台窗口；app 只用 `remote_input && mouse_mode == Relative` 控制隐藏/裁剪。Web
`pointer.js` 已有 Pointer Lock，但把“选择 relative”和“已锁定”分开后仍需补齐区域外
软降级、失焦、Esc、断开和 DOM 清理。#154 与 #156 都会触及 pointer.js、app 输入边界，
不能并行修改同一套调度代码。

### #153

iced `theme.rs` 只覆盖部分自绘 UI，普通 Button/PickList/TextInput/Checkbox 仍落到 iced
默认外观；`modal.rs` 的表单使用纵向 Column，父级 Fill 会使设置弹窗横向撑满。#151 会
新增鼠标 profile 选择器，故视觉统一必须在行为控件稳定后进行。

## 3. 方案与依赖关系

采用“共享模型先行、输入顺序先于捕获、视觉最后收口”的方案：

```text
#151 shared MouseProfile/config/API
   ├── #152 profile load -> control probe
   ├── #156 input scheduling (Iced + Web)
   │      └── #154 local capture boundary (Iced + Web)
   └── #153 visual/layout (last, consumes final controls)
```

严格依赖：

1. #151 必须先完成，#152 的 profile 应用、#156/#154 的模式切换都依赖新的 profile 语义；
2. #152 可在 #151 桌面配置迁移完成后实现，不依赖 Web；
3. #156 必须先于 #154，避免相对消息调度、Pointer Lock 和区域捕获同时改写同一事件路径；
4. #153 必须最后完成，确保新增 profile 选择器、捕获状态和错误状态使用最终布局令牌。

可并行条件：

- #151 的纯共享枚举/解析测试与 #153 的 headless 样式采样可以并行调研，但实现不能并行
  提交，因为 #153 会修改 iced modal/app 文件；
- #152 的根因测试可在 #151 实现期间独立准备，正式接线等 #151 配置字段稳定；
- #156 的 Iced `DeltaSampler` 单测与 Web noVNC 调度单测可以并行开发，但合并前必须一起
  运行，因为二者共享顺序契约；
- #154 的 Windows 光标几何单测和 Web Pointer Lock 状态单测可以并行准备，但接线必须在
  #156 的 flush 入口确定后进行。

不并行的组合：#151 与 #153 的 UI 接线、#156 与 #154 的 pointer.js/app 输入接线、#152
与 #153 的 app/profile 接线。它们会修改相同文件且行为语义有先后关系。

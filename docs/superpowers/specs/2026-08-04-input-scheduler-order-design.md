# 键鼠移动调度与控制事件顺序设计

关联 issue：#156

## 背景

当前键盘、鼠标和滚轮最终都会进入同一条远程输入发送链路，但前端对不同事件的调度策略不一致：键盘事件直接提交，Iced 的鼠标移动由本地状态和 `DeltaSampler` 限频，Web/noVNC 相对模式则对每个浏览器 `mousemove` 立即发送一条相对指针消息。

现有实现还存在两个顺序风险：

1. Iced 在移动尚未达到采样周期时收到按钮或滚轮事件，控制事件可能先于旧移动进入输入队列。
2. Web/noVNC 相对模式没有移动合并，控制事件和滚轮不会统一冲刷待发移动；高速移动会按浏览器事件频率产生发送事件。

底层 RFB 相对指针映射已经在同一消息内按 `RelativeMove -> Button -> Wheel` 处理，CH9329 sink 也保持 pointer batch 内的顺序。因此本设计只调整 Iced 与 Web/noVNC 前端调度，不修改 RFB 协议、输入泵、CH9329 核心层、串口队列或 egui。

## 目标与范围

### 目标

- 键盘按下和释放不依赖鼠标移动采样周期，保持立即提交。
- 鼠标移动单独限频：绝对模式保留最新坐标，相对模式累计位移且不丢失总量。
- 鼠标按钮按下、释放和滚轮作为控制事件，绕过移动限频。
- 控制事件处理前先冲刷待发移动，保证移动、按钮和滚轮的逻辑顺序。
- Iced 与 Web/noVNC 采用相同的调度语义。
- 退出远程输入、断开连接和切换模式时清理待发移动、滚轮及按钮同步状态。

### 不在范围内

- 不修改 RFB 0x08 相对指针消息格式及服务端 pointer mapper。
- 不修改 CH9329 协议、串口 2 ms batch、输入优先级或输入泵。
- 不为键盘引入串口优先级队列。
- 不纳入 egui 桌面端。
- 保留现有约 33 ms 鼠标移动采样周期，不在本 issue 调整频率。

## 现状代码事实

- Iced 的键盘处理在 `crates/ipkvm-desktop-iced/src/app.rs` 中直接调用 `send_key`，没有经过鼠标采样器。
- Iced 绝对移动通过 `last_pointer`、`last_pointer_sent` 和 `POINTER_MIN_INTERVAL` 限频；按钮和滚轮当前通过再次调用绝对发送路径间接处理。
- Iced 相对移动在 `poll_relative` 中读取平台增量，再交给 `crates/ipkvm-desktop-iced/src/relative.rs` 的 `DeltaSampler`。
- Iced 当前在 `UiTick` 中先刷新输入控制器，再轮询相对源，因此控制事件若只等待下一次 tick，可能晚于或早于待发移动形成不稳定顺序。
- Web/noVNC 的绝对模式已有 `_mouseMoveTimer` 和 `_flushMouseMoveTimer`；按钮路径会先冲刷绝对移动定时器。
- Web/noVNC 的本地相对模式补丁在 `third_party/novnc/1.7.0/core/rfb.js` 中直接调用 `relativePointerEvent`，尚无独立的相对移动定时器或累计状态。
- noVNC 的相对消息在服务端被解析为移动、按钮边沿、滚轮的有序事件，因此同一条消息可以承载“待发相对移动 + 最新按钮掩码/滚轮”。

## 方案比较

### 方案 A：Iced 与 Web/noVNC 各自维护前端指针调度器（采用）

在两个前端已有输入边界内增加最小状态：移动状态与键盘路径分离；控制事件通过统一的 flush 入口发送。Iced 复用并扩展 `DeltaSampler` 的累计语义，Web/noVNC 在本地 noVNC patch 中增加相对移动累计和定时器。

优点是改动范围与 issue 一致，能分别覆盖窗口事件和浏览器事件的生命周期，且不改变协议与串口行为。缺点是两端需要各自维护一份相似的调度逻辑，但接口和测试可以保持简单明确。

### 方案 B：在共享输入核心层增加鼠标优先级和合并队列

把键鼠调度下沉到 `ipkvm-core` 或 session 层，前端只提交原始事件。

该方案会改变本 issue 明确排除的 FIFO、串口和核心层行为，且无法自然表达浏览器绝对坐标与 Iced 相对采样的差异，风险和回归面均过大，放弃。

### 方案 C：只调整现有定时器的触发时机

保留各端现有字段，仅在按钮和滚轮路径增加定时器回调或立即发送。

该方案可以缓解部分延迟，但不能完整保存相对移动累计量，也难以保证快速按下/释放边沿不被最终按钮状态覆盖，放弃。

## 采用方案的设计

### Iced 调度

Iced 保持键盘路径不变：键盘按下、释放和修饰键边沿直接调用 `send_key`，不读取或等待任何鼠标采样状态。

绝对模式将“最新坐标”和“已发送坐标”视为独立状态。普通光标移动只更新待发最新坐标，在 33 ms 周期到达时发送；控制事件到达时，无条件使用控制事件发生前的按钮掩码冲刷最新坐标，然后更新按钮掩码并立即发送控制状态。这样按下/释放不会把旧移动改写成新按钮状态，也不会因移动限频而延迟控制事件。滚轮沿同一控制 flush 路径发送，滚轮本身不等待移动周期。

相对模式继续在每个 `UiTick` 从相对源一次性取尽原始增量，累计到采样器中，每个周期最多发送一个移动事件。控制事件到达时先取尽当前相对源，再强制取出采样器内的整数增量；待发增量可以和新的按钮掩码合并为一条相对指针消息，由底层按移动后按钮的顺序展开。即使没有移动，按钮按下和释放也分别发送一条掩码变化消息，不能只保留最终掩码。滚轮也先合并待发移动，再在同一控制路径中发送。

相对采样器需要提供“周期采样”和“控制事件强制取出”两种语义。强制取出只清空已发送的整数部分，浮点缩放余数仍按现有累计规则保留；退出或模式切换时显式 reset，避免旧会话增量泄漏到新模式。

### Web/noVNC 调度

在现有 noVNC 本地 patch 中增加相对移动的待发增量和独立定时器。`mousemove` 在相对模式下先应用灵敏度，再累计到待发增量；首个有效移动可立即发送，之后在 33 ms 窗口内只保留一个待发事件。发送时对累计值截断并限制到 `i16`，只有实际非零的位移才产生移动消息，从而保留累计位移而不是丢弃每个小事件。

相对模式的按钮路径先清理相对移动定时器并取出待发增量，再使用新的按钮掩码发送一条相对消息。这样允许在一条消息内表达 `RelativeMove -> Button`，同时每个按下/释放调用都产生独立掩码边沿。滚轮达到 noVNC 现有步进阈值时沿同一路径冲刷相对移动，再发送滚轮消息；滚轮不等待移动限频。

进入相对模式时清空相对待发状态并保留现有“忽略 pointer lock 初始移动”的行为；退出相对模式、RFB 断开和清理 DOM 时取消相对定时器并清空累计移动。绝对模式继续使用现有 `_mouseMoveTimer`，两种模式的移动状态互不复用。键盘模块与 noVNC 键盘处理不改。

### 事件顺序

控制事件的统一处理顺序如下：

1. 检查连接状态和当前输入模式。
2. 收集前一控制事件之后产生的移动，并冲刷待发移动。
3. 应用新的按钮掩码或滚轮步进。
4. 立即提交控制事件；相对模式允许将第 2 步和第 3 步合并到一条相对消息。

键盘事件仍按到达顺序直接提交；本设计不承诺键盘抢占已经在发送中的串口帧，但不会让键盘等待鼠标移动采样器。

### 错误与生命周期

发送失败继续沿用现有状态消息和连接错误处理，不吞掉调度错误。清理路径必须覆盖：

- Iced 退出远程输入、断开连接、切换到绝对模式。
- Web/noVNC `setRelativeMode(false)`、RFB disconnect、PointerController 退出及 DOM 清理。

清理后不得残留相对增量、绝对最新坐标、滚轮累计值或上一模式的按钮同步掩码。下一次进入远程输入时首个有效移动和首个按钮边沿必须按新会话处理。

## 测试设计

### Rust

- 为 `DeltaSampler` 增加强制取出待发整数增量、周期内继续累计和 reset 后不泄漏的单元测试。
- 在 Iced app 测试中覆盖：键盘按下/释放不等待移动周期；高速相对移动合并且总量保留；绝对移动只保留最新坐标；按钮按下/释放先于控制状态冲刷移动；滚轮先移动后滚轮；快速点击的两个边沿均到达 sink；退出和切换模式清理待发状态。
- 测试 sink 增加跨键盘和指针的有序记录，仅用于验证前端提交顺序，不改变生产输入接口。
- 保留并运行既有 RFB pointer mapper 的 `RelativeMove -> Button -> Wheel` 顺序测试，确认协议层行为未被改动。

### Web

- 在现有 Playwright 浏览器测试中通过 noVNC 相对输入方法注入高频移动，验证同一 33 ms 窗口只产生合并消息且累计位移完整。
- 验证待发移动期间的按钮按下、释放和滚轮均先移动后控制，并验证快速按下/释放产生两个独立按钮掩码。
- 验证退出相对模式后定时器和待发移动清空，重新进入不会发送上一会话残留数据。
- 保留真实浏览器连接、键盘、绝对点击和 pointer lock fallback 回归测试。

验证命令至少包括：

```powershell
cargo fmt --all --check
cargo test --workspace --all-features
node browser-tests/novnc-browser.mjs
```

浏览器测试所需 fixture 按现有 `browser-tests` 入口提供；若真实 pointer lock 或 CH9329 串口时序无法在无头环境稳定自动化，再按 issue 记录人工验证例外、步骤和预期结果。

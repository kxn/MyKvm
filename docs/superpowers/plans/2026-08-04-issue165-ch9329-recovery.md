# CH9329 应答传输与故障恢复实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 让 CH9329 正式串口传输持续消费应答，并在命令无应答或响应错误时自动执行 Reset、等待、GetInfo 验证和全释放恢复，使现有 desktop/headless 程序可以直接验证偶发无响应设备的恢复能力。

**架构：** 保留 `CommandQueue` 的异步调用契约，在 `SerialCommandQueue` 内部使用有界批次通道和单一串口工作线程。工作线程独占串口，按 FIFO 记录待确认命令、持续读取 `Ch9329Decoder` 输出，并在异常时运行恢复状态机；输入调用线程不等待 ACK。

**技术栈：** Rust 2024、`serialport 4.9`、标准库 `std::thread`/`std::sync::mpsc`、现有 CH9329 frame/decoder/response 模块、Cargo workspace。

- [x] **步骤 3：写最小实现**

实现以下结构：

```rust
enum TransportStateKind { Opening, Synchronizing, Ready, Recovering, Offline }

struct PendingCommand { command: u8, sent_at: Instant }

struct TransportState {
    kind: TransportStateKind,
    pending: VecDeque<PendingCommand>,
    response_timeout: Duration,
    recovery_delay: Duration,
}
```

`SerialCommandQueue` 使用 `sync_channel(MAX_QUEUED_BATCHES)` 保存批次，`Arc<Mutex<QueueStats>>` 记录接受数量，`Arc<Mutex<SerialHealth>>` 记录健康状态。`open()` 设置串口 8N1、读写超时 20ms，并启动一个 worker 线程。worker 循环执行：

1. 非阻塞读取批次并在 pending 未满时写入帧；
2. 读串口字节并送入 `Ch9329Decoder`；
3. 解析响应，按 FIFO 校验命令和状态；
4. pending 头超时则进入恢复；
5. 恢复时清空普通输入队列，直接写 Reset，读取并忽略 Reset 响应，等待 2 秒，发送 GetInfo；
6. 收到成功 `Info` 后发送键盘零报告和相对鼠标零报告，清空 pending，恢复 Ready；
7. Reset/GetInfo 失败则关闭当前 worker 端口并进入 Offline；
8. 每次状态变化用 `eprintln!` 输出端口、原因和恢复结果，便于用户立即测试。

Reset 写失败不再重复发送 Reset，直接 Offline；恢复期间新进入队列的普通 batch 可以被丢弃并计数，避免旧鼠标移动在恢复后集中执行。
